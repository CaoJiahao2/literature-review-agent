# 📚 Literature Review Agent

> A single **ReAct Agent** that turns an AI research topic into a structured Markdown literature review — it plans its own searches, calls five academic search tools, self-reflects on coverage and draft quality, and finally submits a grounded report.

## ✨ Features

- 🤖 **Single ReAct Agent** — the LLM drives the whole flow (plan → search → reflect → draft → revise → submit) through native function calling, replacing the deterministic LangGraph pipeline.
- 🔍 **Multi-source tool calling** — five academic sources (arXiv, OpenAlex, Hugging Face Daily Papers, Semantic Scholar, Crossref) are exposed as native function-calling tools the agent invokes on its own.
- 🧠 **Two-step self-reflection** — `review_search_coverage` critiques search coverage and suggests follow-up queries; `review_report_draft` critiques each section and returns revision notes. The agent acts on the feedback before submitting.
- 🧩 **In-run working memory** — the LLM transcript, collected papers, section drafts, and reflection notes live in `AgentState`; papers are deduped by DOI / arXiv ID / normalized title.
- 💾 **Optional cross-run memory** — one JSON snapshot per normalized topic under `~/.lit_review/memory/`; `--resume` injects prior sections and papers as context.
- 🎯 **Citation anti-hallucination** — `submit_report` accepts only section bodies; references are generated by the tool from the real collected corpus, never invented by the LLM.
- 🌐 **English + Chinese** — auto-detects CJK characters; `--language en|zh` to override.
- 📊 **Explainable ranking** — `0.5·citation + 0.3·recency + 0.2·abstract_richness`; cross-source dedupe by DOI / arXiv ID / normalized title (union).
- 🖥️ **CLI + Web UI** — `lit-review review "topic"` for one-shot; `lit-review ui` for a Gradio dashboard.
- 🤖 **LLM client facade** — transparent caching (`LIT_REVIEW_CACHE_DIR`), retry/backoff, token accounting.
- 📊 **Built-in observability** — `--emit-metrics` writes steps, tool calls, reflection rounds, per-source hits, and LLM usage; `--emit-state` writes a debuggable state snapshot.

## 📦 Installation

```bash
git clone https://github.com/CaoJiahao2/literature-review-agent.git
cd literature-review-agent
pip install -e ".[dev,ui]"
cp .env.example .env
# edit .env and set LLM_API_KEY (any OpenAI-compatible endpoint; required)
```

## 🚀 Quick start

```bash
# 1. CLI: search + synthesize
lit-review review "RAG with knowledge graphs" --output reports/rag.md

# 2. Chinese topic (auto-detected)
lit-review review "扩散模型在图像生成中的进展" --language zh --output reports/diffusion.md

# 3. Resume prior memory for this topic
lit-review review "RAG with knowledge graphs" --resume

# 4. Web UI
lit-review ui
# then open http://127.0.0.1:7860

# 5. Show resolved config
lit-review config

# 6. With observability (writes <report>.metrics.json + <report>.state.json)
lit-review review "RAG with knowledge graphs" --emit-metrics --emit-state
```

> ⚠️ Without `LLM_API_KEY`, the program fails fast with a clear configuration error — there is no skeleton fallback.

## 🗂️ Architecture

```
[build system prompt + memory context]
            │
            ▼
   model.bind_tools(TOOLS) ◄──────────────┐
            │                             │
            ▼                             │
   parse AIMessage.tool_calls              │ ToolMessage
            │                             │
   ┌────────┴────────────────┐            │
   ▼                         ▼            │
 search_* × 5        review_search_       │
   │                  coverage            │
   ▼                     │                │
 record_papers     review_report_         │
   │                   draft              │
   ▼                     │                │
 list_papers ──► submit_report ───────────┘
```

The core loop is an **explicit ReAct loop**: each model call returns `tool_calls`, the agent executes them and appends a `ToolMessage` to the transcript, repeating until `submit_report` or `max_agent_steps`.

## 📚 Sources

| Source | Free? | API key | What it gives you |
|---|---|---|---|
| **arXiv** | ✅ | — | Preprints (AI-heavy), full abstracts |
| **OpenAlex** | ✅ | — | Broad coverage, citation counts, venues |
| **Hugging Face Daily Papers** | ✅ | — | Curated trending AI papers (last 7 days), TLDRs |
| **Semantic Scholar** | ✅ | optional `S2_API_KEY` | Rich metadata; rate-limited without key |

## ⚙️ Configuration (`.env`)

```bash
# LLM (any OpenAI-compatible endpoint; required)
LLM_API_KEY=sk-...
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini

# Agent loop
MAX_AGENT_STEPS=12      # max LLM/tool steps
MAX_REFLECTIONS=1       # max rounds per reflection step

# Cross-run memory
MEMORY_DIR=~/.lit_review/memory
RESUME_MEMORY=false

# Per-source per-query caps
ARXIV_MAX_PER_QUERY=15
OPENALEX_MAX_PER_QUERY=15
HUGGINGFACE_MAX_PER_QUERY=20
SEMANTIC_SCHOLAR_MAX_PER_QUERY=10
CROSSREF_MAX_PER_QUERY=10

# HuggingFace trending-papers lookback
HUGGINGFACE_LOOKBACK_DAYS=7

# Default sources (comma-separated)
DEFAULT_SOURCES=arxiv,openalex,huggingface

# Semantic Scholar optional key: https://www.semanticscholar.org/product/api
S2_API_KEY=

# HTTP
REQUEST_TIMEOUT=30
USER_AGENT=LiteratureReviewAgent/0.2 (mailto:agent@example.com)
```

## 🛠️ CLI reference

```bash
lit-review review "topic" [options]
  --output, -o PATH      Markdown output path (default report.md)
  --language, -l en|zh   Report language (default auto-detect)
  --top-k INT            Papers to keep after ranking (default 30)
  --years YYYY..YYYY     Year range (default last 5 years)
  --sources, -s LIST     Comma-separated sources to query
  --resume               Load prior memory for this topic
  --verbose, -v          Stream per-step progress

lit-review ui [--host H] [--port N] [--share]
lit-review config
```

## 🐛 Troubleshooting

- **`LLM_API_KEY is not set` at startup** — expected: the ReAct agent has no skeleton fallback. Set `LLM_API_KEY` in `.env`.
- **OpenAlex 429** — register a contact email and put it in `USER_AGENT` (`mailto=...`), or set `S2_API_KEY` to lean on other sources.
- **`Unknown scheme for proxy URL (socks://…)`** — we disable env proxies by default. To use an HTTP proxy, set `HTTPS_PROXY=http://proxy:port`.
- **Gradio UI won't start** — `pip install -e ".[ui]"` (the base install doesn't pull gradio).
